# МАРС

**МонАрх — Анализ Работы Спецтехники**  
ООО «МонАрх и М»

Демонстрационная система управления техникой: парк, объекты, финансы, смены, путевые листы, табели, обслуживание и склад.

## Render

- Тип: Static Site
- Ветка: main
- Build command: `node --check dist/app.js`
- Publish directory: `dist`
- `SKIP_INSTALL_DEPS=true`

## Подготовка к загрузке исходных данных

Начиная с версии 2.3 новые наборы не содержат демонстрационных машин, видов техники и объектов. Финансовые и оперативные показатели автоматически не создаются. Справочники заполним после проверки исходных таблиц. Разделы «Техника» и «Объекты» показывают понятные пустые состояния.

При открытии данных версии 2.2 удаляются только нетронутые образцы с `demo:true`, не связанные с введёнными записями. Изменённые карточки и карточки, на которые ссылаются операции, смены, ремонты, заявки, фотографии или назначения сотрудников, сохраняются вместе со связанными объектами. До очистки исходный JSON сохраняется в `mars-catalog-archive-v1`; первая копия не перезаписывается. Скачать её можно в настройках. Если архив или очищенный набор сохранить не удалось, исходный набор остаётся без изменений.

Рабочий набор по-прежнему хранится в `mars-working-data-v1`. Прежний ключ `monarch-im-control-v1` не изменяется и не удаляется: его исходный JSON доступен через «Скачать прежние данные». Автоматического восстановления архивов нет: сначала нужна сверка содержимого. При повреждённом текущем файле запись блокируется, а исходный файл можно скачать.

Периоды строятся по датам записей и текущему месяцу. Изменения сохраняются только в этом браузере; общей базы и интеграции с 1С нет. Переключение ролей является предпросмотром интерфейса, а не авторизацией сотрудников. Путевые листы остаются черновиками. Налоги, амортизация и распределение общих расходов по машинам не реализованы.

## Excel / CSV — пакетная загрузка

Раздел «Загрузка данных» принимает XLSX и CSV. Для каждого листа выбираются тип данных, строка заголовков и соответствие колонок. Несколько листов/файлов собираются в один пакет. Связанные объекты, сотрудники и техника могут быть в этом же пакете в любом порядке: проверяются все связи до записи. Сохранение выполняется одним действием целиком; ошибка, нехватка места, изменение данных после предпросмотра или неизвестная ссылка не должны создавать частичный импорт.

Поддержаны семь типов:

| Данные | Куда сохраняются | Связь |
| --- | --- | --- |
| Объекты | Справочник объектов | Постоянный код объекта |
| Техника | Реестр и паспорт | Постоянный код, объект, закреплённый сотрудник |
| Сотрудники | Справочник сотрудников | Постоянный код/табельный номер; учётные записи не создаются |
| Расходы | Финансовые операции | Документ + строка, техника или ОБЩЕХОЗ/СКЛАД, явный объект источника |
| Зарплата | Отдельный реестр для сверки | Сотрудник, период, при наличии техника/объект; без повторного добавления расходов |
| Табели | Исходный реестр в разделе «Табели» | Дата, сотрудник, машина, объект, фактически отработанные часы |
| Путевые листы | Исходный реестр в разделе «Путевые листы» | Документ, дата, сотрудник, машина, объект, показания при наличии |

Скачиваемые шаблоны пустые. Неизвестные и неоднозначные коды блокируются, сопоставление по похожему названию не выполняется. Регистрационный/заводской номер/VIN допустим для ссылки на машину только при однозначном точном совпадении. Существующие карточки загрузкой не перезаписываются. Исторический объект и сотрудник из документа сохраняются независимо от текущего назначения машины; несовпадение явно предупреждается.

Документ должен иметь устойчивый идентификатор: ID из 1С или полный номер с видом/годом, если нумерация повторяется. Нужен постоянный номер строки внутри документа. Повторная загрузка той же пары блокируется независимо от имени файла и изменённой даты. Каждая строка хранит документ, файл, лист и исходный номер строки. Реестр и исходные связи доступны также в паспорте машины. Оригинальные бинарные файлы не хранятся: сохраняются проверенные данные и реквизиты источника.

Лимиты: 8 МБ на файл, 10 000 строк на пакет. CSV поддерживает UTF-8 и явно выбранную Windows-1251. Даты — ДД.ММ.ГГГГ или ГГГГ-ММ-ДД; период зарплаты — ГГГГ-ММ или ММ.ГГГГ. Суммы — положительные, с точностью до копейки. Табель сейчас имеет форму «дата / сотрудник / машина / часы»; месячные матрицы с колонками дней, буквенные коды отсутствий, возвраты/сторно и иные формы нужно адаптировать после получения настоящих файлов, не угадывая их смысл.

Табели и путевые листы загружаются как источники на сверке: они не утверждают смены и не выпускают юридически значимые документы. Зарплата отдельно сверяется с расходами по решению пользователя. Импорт расходов предназначен для подтверждённых затрат: начисления, платежи, авансы и задолженность автоматически не различаются. НДС и другие правила управленческого учёта требуют согласования с бухгалтерией.

Складская закупка исключается из финансового результата, но не создаёт номенклатуру, количество и стоимость поступления. Полный стоимостной склад и распределение ОБЩЕХОЗ по подтверждённым часам остаются отдельными доработками. Сверка возможных ремонтных дублей предупреждает повтор в обоих порядках ввода, но не заменяет идентификацию первичных документов.

Данные остаются в localStorage одного браузера. Эта версия готовит файловый обмен и сверку; общая база, серверная авторизация, резервное копирование и совместная работа сотрудников пока не внедрены. В реальных таблицах сначала необходимо проверить структуры, источники и контрольные суммы.

## Проверки

```sh
node --check dist/app.js
node --check dist/workshop.js
node --check dist/accountant.js
node --check dist/import-engine.js
node --check dist/import-ui.js
node --test tests/*.test.cjs
```

В ограниченном исполнителе можно выполнить `node --test --test-isolation=none --test-reporter=tap tests/*.test.cjs`, чтобы получить результаты каждого теста. Демонстрационные суммы сохранены только в тестовых фикстурах и не подключаются приложением; описания прежних образцов в коде используются только для безопасного распознавания неизменённых карточек при очистке.

Timeweb App Platform может публиковать ту же ветку `main`: HTML/CSS/JS, директория `/dist`. Перед слиянием необходимо проверить фактическое автоматическое развёртывание. Подготовка этой версии сама по себе не публикует сайт.
