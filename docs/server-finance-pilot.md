# МАРС — план перехода к общим данным (пилот)

Статус: проектирование. Эта ветка не подключена к рабочему сайту. Не деплоить и не менять main без согласования.

## Текущее положение (проверено по README.md и dist/accountant.js)
- Сайт — статический HTML/CSS/JS, данные живут в localStorage каждого браузера.
- Роли пока являются переключателем интерфейса, не реальными учётными записями.
- Импорт бухгалтерии сейчас рассчитан на расходы по шаблону CSV/XLSX; реальные ежемесячные книги содержат также выручку, зарплату, топливо, ремонт и итоговую прибыль.
- Реальная база данных и серверный API отсутствуют.

## Цель пилота
Один ответственный загружает проверенные месячные показатели за июль–сентябрь 2026 года. Директор с другого устройства видит те же цифры по каждой машине, месяцу и группе. Позже право импорта передаётся бухгалтеру.

## Архитектура
1. Существующий интерфейс MARS (Timeweb App Platform, статический сайт).
2. Отдельное серверное приложение (API), доступное только по HTTPS; проверка прав пользователей и файлов на сервере.
3. PostgreSQL с резервным копированием; доступ к базе только у сервера, никогда напрямую из браузера.
4. Файлы Excel разбираются на сервере; оригиналы и результаты сверки хранятся с привязкой к импорту и контрольной сумме.

## Минимальные таблицы
- users (id, role, password_hash / безопасный внешний провайдер авторизации)
- machines (id, canonical_identifier, type, plate, aliases)
- reporting_periods (id, year, month, status)
- machine_monthly_finance (machine_id, period_id, revenue, fuel, repairs, payroll, other_expenses, reported_expenses, reported_profit, source_import_id, review_status)
- imports (id, file_name, checksum, uploaded_by, created_at, status)
- import_issues (import_id, row_reference, code, message)
- audit_log (actor, action, entity, timestamp)

Уникальность: (machine_id, period_id, источник/версия) и запрет повторного применения одной версии импорта. Денежные суммы — decimal, не float.

## Правила импорта
- Импорт сначала в «предпросмотр», не в рабочие финансовые отчёты.
- Проверять идентификаторы техники, месяц, категории, обязательные поля и арифметику; не создавать машины автоматически.
- Сводные книги «ФОРМАТ» не считать дополнительными хозяйственными операциями.
- При обнаружении спорных строк блокировать утверждение соответствующего периода до решения ответственного.
- Отдельно сохранять исходную прибыль и вычисленную «выручка минус расходы»; не исправлять молча.
- Нельзя одновременно считать сумму «ремонт» из Excel и отдельное списание механика как два независимых расхода без сверки.
- Закупка на склад не становится расходом машины до подтверждённого списания; зарплата, накладные и амортизация требуют согласованной методики.
- Повторная загрузка того же файла не создаёт дублей; замена периода требует явного подтверждения, истории версий и возможности отката.
- Часы вида «293 (170)» не интерпретировать до расшифровки.

## Проверки на реальных исходных таблицах
- Audi A6 М 984 АХ 777, август: выручка 49 500 ₽, расходы 0 ₽, прибыль 0 ₽ — расхождение.
- Ford Focus С 710 НС 77, август: выручка 33 900 ₽, расходы 0 ₽, прибыль 0 ₽ — расхождение.
- Audi A6 М 984 АХ 777, сентябрь: выручка 49 600 ₽, расходы 0 ₽, прибыль 0 ₽ — расхождение.
- Сентябрьский файл «Авто» ошибочно подписан внутри как июль; месяц должен подтверждаться оператором.
- Не публиковать финансовые показатели в открытом доступе: текущий публичный сайт не имеет полноценной авторизации.
